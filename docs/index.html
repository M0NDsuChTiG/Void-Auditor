FEATURES

  • Risk score 0–100 from 6+ checks: ADB Wi‑Fi, Accessibility services, SELinux, overlays, banking apps
  • Fix hints are offered as confirmable capabilities — never raw shell commands
  • Every check is written to TRACE together with the policy decision

  • Scans external cache of user apps; dry-run shows sizes before anything is removed
  • PURGE needs a typed phrase + explicit confirm (3-factor), with per-app selective clean
  • Honest EXTERNAL_CACHE_ONLY — internal /data/data without root is reported, never faked

  • Subnet discovery: one Shizuku batch of parallel pings — about 3 s per /24
  • MAC from /proc/net/arp with vendor lookup; common TCP ports on live hosts
  • Full 1–65535 scan with service detection and banners; cancellable from the UI

  • Status is read only from getprop — no fake “enabled”
  • Enable verifies the port actually answers, otherwise SETPROP_FAILED / VERIFY_FAILED
  • Reports SELinux blocks on non-root devices honestly

  • Gemini proposes Intent Proposals with whitelisted capabilityId — advisory only
  • Pipeline: sanitize → validate → human review → PolicyEngine → execute → audit
  • AI never runs shell directly; destructive operations are not in the whitelist

  • Finance packages: dangerous permissions (SMS, call log, contacts), WebView, deep links
  • Detects persistent background services and accessibility risk indicators
  • Results feed the risk score with a clear DETECTED / OK status

  • Per package: force-stop, disable, clear data, activity launcher
  • Destructive actions require explicit confirmation via risk-tiered dialogs
  • Package list with status: running / frozen / disabled

  • TRACE timeline: actor, capability, risk, policy decision, exit code, duration
  • Written to app-private storage; export via MediaStore when needed
  • ActorType distinguishes USER decisions from AI decisions

Requires Android 8.0+ · Shizuku v13+

KNOWN LIMITS

Internal /data/data cache is often invisible without root. The app shows EXTERNAL_CACHE_ONLY and may offer SYSTEM_TRIM — it does not pretend to see full internal cache.
ENABLE_WIFI_ADB via setprop is blocked by SELinux on many non-root devices. Failures are reported as SETPROP_FAILED or VERIFY_FAILED, never as a false “enabled”.
