# VOID Auditor — Отчёт по NET_SCAN

**Версия:** 1.4.3 (code 7) · **Обновлено:** 15.08.2026  \
**Устройства тестирования:**
- Samsung SM-A115F (`R9HN50GZL4J`, Android 11) — debug APK (SKIP_BIOMETRIC=true), release APK
- ChromeOS (`13.13.213.117:5555`) — debug APK

---

## 1. Задача

Вкладка `NET_SCAN`:
1. Полный скан всех портов 1–65535 (по требованию пользователя).
2. Отмена скана (кнопка `CANCEL`).
3. Больше информации о найденном хосте: открытые порты + определение сервисов (баннеры).
4. Скорость: полный скан не должен занимать «часы».

## 2. Реализация

### `network/NetworkScanner.kt`
- `COMMON_PORTS` — без дублей: `22, 53, 80, 443, 445, 5555, 8080, 8443, 9090, 3389, 5900` (в v1.4.3 добавлены **53 (DNS)** и **445 (SMB)** — именно они реально открыты на домашнем шлюзе).
- `FULL_PORTS = (1..65535)` — режим «все порты».
- Таймаут TCP-connect: **150 мс** (LAN-ответ приходит за миллисекунды; таймаут нужен только для потерянных/фильтруемых SYN).
- **Параллельность 32 + до 4 проходов + адаптивная пауза** (вместо старых 256):

  > ⚠️ Почему не 256: замеры на шлюзе `13.13.213.111` показали, что при шквале 256 одновременных коннектов роутер переполняет SYN-очередь и **молча теряет ~70% открытых портов** (256 → 31% успеха, 64 → 78%, 32 → 91–96%, последовательно → 100%). Под постоянной нагрузкой без пауз роутер коллапсировал до <20% даже при 32. Поэтому: порции по 32, не ответившие порты повторяются до 4 проходов, между порциями — пауза 80 мс, когда предыдущая порция упёрлась в таймаут (на здоровых сетях — без замедления).
- **Баннер-детект сервисов** на открытых портах (`grabServiceBanner`):
  - HTTP-порты (80, 8000, 8080, 8081, 8888, 9080, 3000, 5000): шлётся `GET / HTTP/1.0` → считывается первая строка ответа;
  - остальные порты: чтение приветственного баннера (SSH/SMTP/FTP/…);
  - санайт-строка: только печатные символы, максимум 64 символа;
  - если баннер пустой — подставляется известное имя порта (`53 → DNS`, `22 → SSH`, `5555 → ADB` и т.д.).
- Отмена: полный `CancellationException` проброс через `coroutineScope` → `scanJob.cancel()`.

### `network/NetworkProfile.kt`
- `HostInfo` расширен полем `services: Map<Int, String>` (порт → баннер/имя сервиса).

### `network/NetworkDashboard.kt`
- Переключатель `COMMON PORTS` / `ALL 1-65535`, кнопка `CANCEL` во время скана.
- Двухуровневый прогресс: `host 1/5 • port 45000/65535`.
- Live-появление хостов по мере завершения каждого (`onHostResult`).
- Карточка хоста: `Open: 22, 5555` + строка сервисов `22: SSH-2.0-OpenSSH_8.4p1`.
- Диалог хоста при тапе: HOSTNAME, MAC, VENDOR, RTT, ALIVE, OPEN PORTS, **SERVICES** — каждая строка с кнопкой копирования, плюс `COPY ALL (JSON)` (включая `"services":{...}`) и `DISMISS`.
- Копирование логируется в консоль: `COPIED KEY → value`.

## 3. Результаты измерений (телефон, сеть 13.13.213.0/24)

### 3.1 Стабильность обнаружения (главный фикс v1.4.2/v1.4.3)

| Параллельность | Успешных коннектов к реально открытому порту |
|---|---|
| 1 (последовательно) | 5/5 (100%) |
| 16 | 15/16 (94%) |
| 32 | 29/32 (91%) |
| 64 | 50/64 (78%) |
| 128 | 41/128 (32%) |
| **256 (старый сканер)** | **79/256 (31%)** |

Под постоянной нагрузкой без пауз (шквал от самого скана): **16 → 18%, 32 → 6%, 64 → 14%** — очередь роутера никогда не дренируется. После ~5 с тишины: 32 → **96%**. Паузы между порциями восстанавливают ~88% в среднем.

**Проверено на устройстве после фикса:**
- Полный скан нашёл **`5555 (ADB)`** на `13.13.213.117` — порт, который старый 256-параллельный скан потерял бы с вероятностью ~70% (подтверждено `nc` с телефона).
- COMMON-скан шлюза `13.13.213.111` показывает **`Open: 53 • 53: DNS`** (раньше — `NONE`, потому что 53 не было в списке и SYN терялись).

### 3.2 Скорость

| Параметр | Было (256 пар., 350 мс) | Стало (32 пар., 150 мс, 4 прохода) |
|---|---|---|
| Полный скан 65535 портов на 1 хост | ~2.5–3 мин | ~2.5–3 мин (1-й проход), до ~6–8 мин с повторными проходами на капризных роутерах |
| Скан COMMON (11 портов) на хост | ~8–10 с | секунды |

Прогресс корректно живёт между хостами: `host 1/5 • port 44296/65535` → `host 2/5 • port 13014/65535`.

Найденные хосты в тестовой сети: `13.13.213.115` (сам телефон), `13.13.213.111` (MoNDsuChTiG.lan, MAC `18:31:BF:53:5C:EC`), `13.13.213.117` (ChromeOS, ADB 5555).

## 5. Наблюдения / замечания

1. **Баннеры**: у `13.13.213.111` открытый порт `53` — при отсутствии текстового баннера отображается имя сервиса из справочника (`DNS`), не «пустая строка». Порт 53 теперь входит в `COMMON_PORTS`.
2. **Собственный IP** попадает в результаты скана (ping самого себя возвращается) — ожидаемо, не баг.
3. **Капризные роутеры**: если роутер душит SYN под нагрузкой, сканер сам замедляется (паузы + повторные проходы) — полный скан может занять до ~6–8 мин, но результат достоверный. Тайминг ниже 150 мс рискован (потеря медленных устройств в WiFi).
4. **Биометрия**: release-сборка требует биометрическую аутентификацию; для автоматических тестов по adb используется debug-сборка (`SKIP_BIOMETRIC=true`).
5. **Версия**: фикс порт-скана вошёл в релиз **v1.4.2**, финальное состояние (53/445 в COMMON_PORTS, SYS-аудит) — в **v1.4.3**.
